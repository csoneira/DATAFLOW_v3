# 2026-10-22
## Muon energy reconstruction from time of flight
---

### Scope

Today I revisited an old, largely independent detector-physics test: estimating muon energy from time-of-flight (TOF) measurements across several equidistant detector planes. This is **not part of the production MINGO analysis pipeline**; it is kept as an ancillary calculation because it is useful for understanding what detector geometry and timing resolution would be required for TOF-based energy reconstruction.

The study assumes:

- `m` equidistant detector planes spanning a total distance `d`;
- an independent Gaussian timing uncertainty `sigma_T` on each plane;
- a straight-line least-squares fit of time versus detector position;
- velocity obtained from the fitted TOF slope;
- total relativistic muon energy reconstructed from that velocity.

The energy variable in this study is **total relativistic energy**, not kinetic energy.

### Main detector-design scaling

For a straight-line fit to `m` equally spaced positions between `0` and `d`,

\[
S_{xx}=\sum_i (x_i-\bar{x})^2
      =\frac{d^2 m(m+1)}{12(m-1)}.
\]

With independent timing errors of standard deviation `sigma_T`, the fitted TOF slope has uncertainty

\[
\sigma_{\mathrm{slope}}=\frac{\sigma_T}{\sqrt{S_{xx}}}.
\]

For moderate or large `m`,

\[
\sigma_{\mathrm{slope}}
\simeq
\frac{\sqrt{12}\,\sigma_T}{d\sqrt{m}}.
\]

Therefore the most useful compact rule coming from this study is approximately

\[
\boxed{\mathrm{TOF\ figure\ of\ merit}\;\propto\;\frac{d\sqrt{m}}{\sigma_T}}
\]

with larger values being better.

This is the main conclusion to remember. The lever arm enters linearly, while the number of planes only helps as `sqrt(m)`. As a rule of thumb, **doubling the total detector distance gives approximately the same TOF-slope improvement as quadrupling the number of planes**, provided the timing resolution per plane remains the same.

### Why the method deteriorates rapidly at high energy

The reconstructed total muon energy is

\[
E=\frac{m_\mu}{\sqrt{1-\beta^2}},
\qquad \beta=v/c.
\]

Propagating a small velocity error gives approximately

\[
\frac{\delta E}{E}
\approx
\gamma^2\beta^2\frac{\delta v}{v}
\simeq
\gamma^2\frac{\delta v}{v}
\quad (\beta\approx1).
\]

This makes the inverse problem intrinsically ill-conditioned for relativistic muons. Once the muon is already very close to `c`, a very small TOF error produces a large energy error. The scan therefore shows the expected qualitative behaviour:

- TOF reconstruction is most promising at the lower end of the studied energy range;
- improving `sigma_T` is extremely important;
- increasing `d` is very effective because it directly increases the measurable TOF difference;
- increasing the number of planes helps, but with diminishing returns proportional to roughly `sqrt(m)`;
- multi-GeV reconstruction from TOF alone becomes difficult unless the timing resolution and lever arm are exceptional.

### Code cleanup and numerical treatment

The original March-2025 script was preserved conceptually: the same TOF model, energy conversion and four requested parameter-dependence plots remain. I made only targeted changes so the study is practical to keep and rerun:

1. The original dense extended scan contains `100 x 96 x 100 x 100 = 96,000,000` parameter combinations, with `10,000` simulated measurements at every point. Running that literally is not practical for routine use.
2. With independent Gaussian timing noise, the least-squares fitted slope is itself exactly Gaussian, with
   `sigma_slope = sigma_T / sqrt(Sxx)`. The default implementation therefore evaluates the expected energy residual directly from this slope distribution using Gauss-Hermite quadrature. This keeps the same statistical model while avoiding explicit `m x num_samples` timing arrays at every point.
3. A Monte Carlo mode remains available for a stochastic calculation closer in spirit to the original implementation.
4. The default grid spans the same physical parameter ranges but uses fewer points. `--full-grid` restores the original dense grid explicitly.
5. The original plotting section projected a four-dimensional cloud directly onto two-dimensional coordinates, so the same `(x,y)` pair could occur with many different residual values. The revised code averages over the two nuisance variables first, yielding one well-defined residual per point in each contour plot.

The four output views remain:

- energy vs timing resolution;
- energy vs number of planes;
- timing resolution vs number of planes;
- detector distance vs number of planes.

Residuals are still clipped at 50% for plotting, following the original script. A saturated region must therefore be read as **50% or worse**, not as exactly 50%.

### Caveat on unphysical fitted velocities

As in the original script, noisy fits can occasionally imply `v > c`. The code protects the relativistic square root numerically by enforcing a small positive denominator. That keeps the scan finite, but such cases should ultimately be treated as failed or unphysical reconstructions rather than as ordinary energy estimates. A future refinement could report the fraction of these failures separately.
